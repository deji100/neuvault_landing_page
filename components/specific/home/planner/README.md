Planner is the second animated section, after CaptureDemo. Its reversible 106-second timeline uses the native desktop sidebar, planner views, item sheet, document picker, Nova robot and Nova proposal/confirmation styles. The opening still creates “Review API architecture,” attaches a captured note and PDF, reschedules it in Week, reopens it in Month, and completes it through Board.

The AI segment now demonstrates two multi-action messages. In the first, one request prepares four proposals: create two tasks, create a release-readiness event, and reschedule the existing staging deployment from November 13 to November 16 at 10 AM. One Confirm all 4 action at 62 seconds starts the sequence; each change appears automatically between 62.8 and 65.2 seconds. No task, event or date changes while the proposals are only being reviewed.

The second request moves both new tasks to In progress and completes an existing retry-and-idempotency task. One Confirm all 3 action at 89 seconds applies the changes between 89.8 and 91.4 seconds. The cursor never visits individual proposal buttons or manually drags these tasks. Board shows both moved tasks and the completed work, then Month shows the new tasks/event and the deployment on its new date. The completed original review and its source connections remain intact.

plannerProject.ts is the single source for prompts, proposal types, confirmation/application times and resulting item state. It uses CREATE_ITEM, UPDATE_ITEM, MOVE_TO_STAGE and COMPLETE_ITEM operations supported by desktop's plannerNovaCore.ts. All views and proposal statuses derive from the same reversible clock; seeking backwards removes later changes without mutating the base data. PlannerNovaDemo.tsx keeps the native multi-proposal and Confirm all layout and shows applying/done states. All responses are scripted demonstration data: no AI, planner API, database or real user content is accessed.

The calendar uses fictional November 2026 content anchored to November 8. Native planner/robot rules live in capture/DesktopApp.css, synced by scripts/sync-desktop-tour-styles.cjs. PlannerInterface.module.css confines the panel to the scaled viewport. Cursor movements take 450ms and card drags take 600ms, with stationary pauses so prompt typing and result-reading time remain unchanged. usePlannerTour.ts owns timing, measured cursor targets, view changes and offscreen/hidden-tab pausing; reduced motion shows the complete final calendar without playing the tour.
